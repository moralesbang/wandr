# Factory V1.4

Date: 2026-11-27

## The need

The factory uses one acceptance-test-first entry flow for every issue. Risk changes the reviewers, but a small styling or documentation task still needs a test writer and a verified red. Frontend, backend and full stack work need different context and evidence without separate copies of the orchestration system.

## What V1.4 changes

The current definition is in [`factory/README.md`](../README.md).

- **Classification before implementation.** The orchestrator proposes scope, complexity, exact expected paths, behavior impact, evidence, uncertainty and verification. `factory route` validates the input and persists the policy's decision. Risk declared in the issue remains a floor.
- **Four workflows.** Light work skips the separate acceptance-test writer and mandatory red, while retaining complete checks and independent review. Standard work keeps the existing acceptance-test-first flow. Reinforced work applies high-risk controls and impact analysis. Research resolves uncertainty before implementation or a PR.
- **Independent dimensions.** Frontend, backend, full stack, tooling and docs are profiles; small, standard and uncertain describe complexity. Neither dimension implies low risk.
- **Conservative light eligibility.** Only low-risk, small, known nonbehavior work entirely within `README.md`, Markdown in `docs/`, or CSS in `apps/web/src/` qualifies. JSX/TSX copy changes remain standard. Tests, configuration, dependencies, sensitive paths and protected rules cannot qualify through a small-task claim.
- **Research stays read-only.** Before classification and during research, the guard allows exploration and the orchestrator's proposal, research report or Decision Request writes. Routing proposal and research files are sealed with the build rationale during blind review. Only the orchestrator runs `route`; the persisted plan stays in CLI-owned state.
- **Routing follows the diff.** Observed scope and sensitive paths can require a stronger workflow and risk. Earlier requirements cannot be downgraded by submitting a new proposal. Existing jobs retain the legacy standard behavior.
- **Scope-specific evidence.** Existing agents use the relevant contract and testing level instead of forcing every task through a browser. Light work needs independent AC evidence in the reviewer report, not artificial tests for a red.

## Boundaries

This version changes routing only. It does not filter CI by changed paths, change merge authority, relax protected paths, replace independent review or fix unrelated factory issues. All executable routes run the complete local CI checks. Cost reductions are a hypothesis to measure, not a promised percentage.

## Validation

- Factory unit and behavioral suite: **1,992 passed, 0 failed** across 52 files. Includes routing policy, persistence, untracked/staged/committed escalation, research isolation, lightweight gates, independent AC evidence and stale-review rejection.
- Workspace lint, typecheck and build passed; unchanged workspace tasks reused Turborepo's local cache. Format and `git diff --check` passed.
- The suite's HTTP-server tests were run outside the restricted sandbox, which cannot open local ports.
- Real-service integration and browser E2E checks remain pending locally: Docker's socket is unavailable, including outside the sandbox.
- A real V1.4 job has not yet established time or cost savings.

## Sources behind the design

- [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents): simple composable workflows, routing to specialized work and adding complexity when it earns its cost.
- [Google Engineering Practices: Small CLs](https://google.github.io/eng-practices/review/developer/small-cls.html): self-contained changes and reviewable scope.
- [DORA: Working in small batches](https://dora.dev/capabilities/working-in-small-batches/): faster feedback and avoiding regrouping small work downstream.
- [Felderer and Schieferdecker: A taxonomy of risk-based testing](https://arxiv.org/abs/1912.11519): adjusting verification effort through risk assessment and reassessment.
