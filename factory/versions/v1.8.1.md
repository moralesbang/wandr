# Factory V1.8.1

Date: 2026-11-28

## The need

Job #15's [`/postmortem`](../../.claude/skills/postmortem/SKILL.md) found guards and agent text that misfired, each one a patch (a part that decides more than it was meant to, or says the wrong thing). Its evidence, from the report's Friction section:

- **R1, the guard reads an interpreter's heredoc body as shell.** The test agent's `python3 - <<'EOF' … EOF` edits were denied three times (04:10:01, 04:10:06, 04:10:27): twice as "a walk … rooted in factory/.jobs/ … is not yours to make from there", once as "The test agent writes only acceptance.md in the job folder", though that was the only file written. `RUNS_HEREDOC` listed `python3?|node|bun|perl|ruby` beside the shells, so the body's Python became shell calls (`(1 if int(m.group(2))>=294 else 0)` parsed as a write to `factory/.jobs/15/=294`). Cost: 3 denials, about 30 s, and a retry of the identical command on a message that named a grep that wasn't there.
- **R2, a bare assignment is read as `env`.** `J=factory/.jobs/15; ls $J; cat $J/issue.md` was denied before routing twice (03:36:10, 03:40:39): "only read-only investigation runs: `env` is not allowed". 2 denials, about 6 s.
- **R3, TypeScript configs are protected by name.** Denied `.typecheck-fixture-manual/tsconfig.json` at 03:46:37, the test agent wrote the same content as `check.json` five seconds later and changed its committed acceptance test to use that name. The denial is intended; the rename is not, and `tsc -p` would have accepted any name.
- **R4, `write.denied` names the repo for a path outside it.** An edit of `~/.claude/settings.json` before routing (03:38:28) was denied with "the repo is read-only". Right verdict, wrong place named.
- **A1, writers send scratch output to Claude Code's scratchpad.** 3 denials (03:46:00, 04:02:42, 04:10:43), about 15 s. `factory-test.md` and `factory-build.md` said "a file you can read (a reviewer's sandbox)", copied from the reviewers: a writer has no sandbox. `factory-test.md` named no scratch place, and the build agent ignored its own "keep scratch output in the worktree".
- **A2, "with a timeout" is read as GNU `timeout`.** 2 runs of `timeout <s> bunx playwright test` (03:47:09, 04:10:46) failed with "command not found: timeout" on macOS. About 5 s.
- **The audit's source list.** `postmortem-audit` named `cognition.ai/blog`, which redirects to `cognition.com/blog`.

The plan's other entries ship in later versions.

## What it changes

- **R1 (FI-013).** `RUNS_HEREDOC` in [`bash-words.ts`](../cli/src/bash-words.ts) lists shells only (bash, sh, zsh). An interpreter's heredoc body is data and the call is judged as the interpreter's: a reviewer's `python3 -` outside sandbox exec is still denied, naming python3. Defended by [`hook-heredoc.acceptance.test.ts`](../cli/src/commands/hook-heredoc.acceptance.test.ts).
- **R2 (FI-013).** `outsideExec` in [`bash-policy.ts`](../cli/src/bash-policy.ts): a call that only assigns variables runs no program. A bare `env` is still `env`. Same acceptance file.
- **R3 (FI-005).** A `.json` whose content has `compilerOptions`, or an `extends` naming a tsconfig, is a TypeScript config whatever its name: `isTsConfigText` in [`paths.ts`](../cli/src/paths.ts), used by `writePolicy` in [`write-guard.ts`](../cli/src/write-guard.ts) and `typescriptVerdict` in `bash-policy.ts`. `tsc -p` and `--project` from the test and build agents must name a protected tsconfig or an existing folder (its own `tsconfig.json` is protected by name); any other file, with or without an extension, is denied. Defended by [`hook-ts-config.acceptance.test.ts`](../cli/src/commands/hook-ts-config.acceptance.test.ts).
- **R4 (FI-012).** Before routing, a write outside the worktree is denied with text naming where it leads (Claude Code's `~/.claude` files, or outside the worktree), not "the repo is read-only". [`write-guard.ts`](../cli/src/write-guard.ts); [`hook-outside.test.ts`](../cli/src/commands/hook-outside.test.ts).
- **A1 (FI-012, message).** The writer agents ([`factory-test`](../../.claude/agents/factory-test.md), [`factory-build`](../../.claude/agents/factory-build.md)) keep scratch output in `.scratch/` at the worktree root (gitignored, deleted before commit); "(a reviewer's sandbox)" is gone from their text, and [`factory-diagnose`](../../.claude/agents/factory-diagnose.md) reads output in the foreground. The guard's denial of a write outside the worktree names `<worktree>/.scratch/` for those two agents (`classifyWrite` and `SCRATCH_DIR` in [`visibility.ts`](../cli/src/visibility.ts)). Tests: [`agent-text.test.ts`](../cli/src/agent-text.test.ts), [`hook-scratch.test.ts`](../cli/src/commands/hook-scratch.test.ts).
- **A2.** Every factory agent says "with the Bash tool's `timeout` parameter (macOS has no `timeout` command)". `agent-text.test.ts`.
- **The audit's sources.** [`postmortem-audit.md`](../../.claude/agents/postmortem-audit.md) lists `cognition.com/blog`, where `cognition.ai/blog` redirects.

## What was learned

- **R2's plan said to deny an unresolvable `$VAR` operand; it isn't denied.** Before routing the orchestrator may already read any literal path, so `ls $J` widens nothing a literal doesn't.
- **Assignments are not judged as a program in either form.** `PATH=/x cat a` and `PATH=/x; cat a` are both allowed to a reviewer outside sandbox exec, so a reviewer could run a scratch script named `cat` from its sandbox. This predates v1.8.1 (the prefix form was always allowed). An open gap, not fixed here.
- **The content check of a Bash write reads the whole command text.** A command that writes any `.json` and contains `compilerOptions` anywhere is denied, an accepted over-approximation. An Edit of an already existing, differently named TypeScript config whose new text holds neither key is not caught.
- **A denial answered by a rename (R3) is closed at the run (`tsc -p`), not only at the write.**
