# Factory V1.5

Date: 2026-11-27

## The need

V1.5 is the lean, self-hosting factory. The project's first goal is to show how an agentic coding system is built, so the factory has to be legible (docs from general to specific, each fact in one place), principled (numbered invariants that act as its acceptance criteria) and able to change itself through its own lane, judged against those invariants.

## What it changes

The definition is in [`factory/README.md`](../README.md).

- **Dead code and needless exports are gone from the CLI.** `gitCommand` and `PRICES_EFFECTIVE`, which nothing used, are deleted; the prices' effective date stays as a comment above `PRICES`. 77 symbols that no other file uses lose their `export`, and the re-exports of `REVIEWER_ROLES` from `seal.ts` and `COPIED_WORDS` from `commands/lifecycle.ts` are dropped. Tests and the `factory watch` page, which loads `watch/state.ts`, count as users. No behavior changes.
- **The factory comes first.** `CLAUDE.md` states the project's first goal, showing how an agentic coding system is built while the whole project is managed with AI, and judges every proposal first by the decision it shows in the factory (its isolation, its gates, its routing), then in the product. The root `README.md` says the factory is half of the project.
- **Docs from general to specific.** The 675-line `factory/README.md` becomes a short overview (the goal, the promise, one flow diagram, routing and workflows, the actors) and three docs under `factory/docs/`: isolation, quality and operating. Reference the code already holds is linked, not copied: the command table gives way to `bun run factory`'s usage, the model and effort table to `LAUNCH_TABLE`, each agent's inputs to `visibility.ts`, the protected and sensitive path lists to `paths.ts` and `risk.ts`. Nine diagrams become three. `CLAUDE.md` records the rule: each fact lives in one place. This record follows a shorter template: the need, what it changes, validation, what was learned.
- **The factory invariants.** [`knowledge/standards/factory-invariants.md`](../../knowledge/standards/factory-invariants.md) lists 23 numbered guarantees (`FI-001`…), each with the mechanism that enforces it and the tests that defend it today, derived from the docs and from every refusal in the CLI and the guard. The refusals no invariant covers are listed apart for the user to judge. A factory test that defends an invariant is an acceptance test that names its id; every other factory test needs a T-009 value record.
