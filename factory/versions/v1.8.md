# Factory V1.8

Date: 2026-11-27

## The need

Two of the factory's versions came from reading a job's log by hand. V1.1 came from job #13 stopping after its red. V1.7 came from job #15 (65 minutes, about $8, no PR), where an audit of `events.jsonl` found the factory changing under the job, 54 denied hand-backs, 13 minutes lost to Docker being down, and a review that cost more than the work it checked. Each audit was a one-off: nothing said what to look for, where a cause belongs, whether the log was enough to tell, or how big a change each fix makes. And each one only added: every version so far grew the factory, and none weighed it against how others build with Claude Code, where a part may already be cheaper, native or unneeded. Nothing said what a version number means either: every version had been a `v1.x`, with no written rule for the bump.

## What it changes

- **`/postmortem <n>`, a user-invoked skill** ([`SKILL.md`](../../.claude/skills/postmortem/SKILL.md)). It places each piece of unexpected friction in one layer: the rules, the skill, the agents or the deterministic part. In the skill and the agents it also tells a wrong instruction from a model that ignored a clear one. It judges whether the evidence was enough and turns each gap into a fix for the factory's observability. It explains everything to the user, invented examples first and then the job's own, and proposes a plan only after the user confirms they understood. Each fix in the plan carries its layer, its invariant, the test that proves it and its bump. The report is `factory/.jobs/<n>/postmortem.md` in the main checkout, beside the log. An approved plan becomes the next record's **The need**, so each fact keeps one home.
- **A blind pace judge**, [`postmortem-timing`](../../.claude/agents/postmortem-timing.md), on Opus. It starts in the background before the skill's own analysis and never sees it. It cuts the log into phases and sets an ideal against each one, anchored on the durations the log measures. It accounts for every minute past the ideal as waiting, denial loop, rerun, rework or overhead, and rules each phase right, slow or suspiciously fast. The skill then crosses the two readings and puts each disagreement to the user. It is the review's blind-first pattern, applied to the factory itself. It runs outside any job, so it is not a `factory-*` agent, has no `launch` plan and is not among the frozen files.
- **A blind factory auditor**, [`postmortem-audit`](../../.claude/agents/postmortem-audit.md), on Opus, launched beside the pace judge. It weighs every part of the factory against current practice, Claude Code first, and rules each one keep, edit, remove or add, removals weighed before additions: a factory improves by losing parts as much as by gaining them. Each change states its saving in tokens or steps, anchored on the runs the job measured, and names the guarantee it touches and the part that keeps it, because the isolation and the gates are what the factory exists to show. It reads only a fixed list of English sources (Anthropic's docs and engineering writing, agent builders, practitioners who build with agents and write about it) and no forums, under a budget of 15 pages: a source off the list is proposed to the user, never cited, and the skill drops any change resting on one. Each audit starts from the last, so a second one searches only what was published since. The user keeps or sets aside each change, and the plan sizes the kept ones like any fix.
- **What a version number says** ([`versions/README.md`](README.md)). The bump follows the factory's contract: major when who decides what changes, minor when what a part decides changes, patch when a part that misfires is fixed to decide only what it always meant to.
- [`operating.md`](../docs/operating.md) says when to run a post-mortem (before `factory clean`, which removes the handoff folder) and where its files live.

## Validation

- Not run yet: a post-mortem of a real job. Job #15 is the first candidate.
- No CLI change: `agent-frontmatter.test.ts` checks only `factory-*` agents, so the two new agents are outside it.

## What was learned

- **A clean erases half the evidence.** The state and the log survive in the main checkout, but the handoff folder (build notes, reviews, diagnosis, Decision Requests) goes with the worktree. The transcripts survive in `~/.claude/projects/`, under the worktree's project folder, not the main checkout's.
- **Agreeing on the cause comes before the plan.** A plan proposed on a cause the user hasn't followed can only be accepted or rejected whole. The skill ends its turn after the explanation for that reason.
