# Factory V1.1

Date: 2026-11-26

## The need

The first real job, #13 (a favicon and app icons), stopped right after its red commit: no agent, and not the orchestrator, could write its handoff files. V1 kept the job's folder, `factory/.jobs/<n>/`, in the main checkout, and the orchestrator enters the job's worktree after `factory start`.

- From `EnterWorktree` on, Claude Code confines the session and every subagent to that worktree. A `Write` or `Edit` in the main checkout is refused: "This session is isolated in the worktree … Edit the worktree copy of this file instead of the shared-checkout path."
- Writing the worktree's copy, `<worktree>/factory/.jobs/<n>/acceptance.md`, reached the guard hook as a repo path under `factory/**`, a protected path: "factory/.jobs/13/acceptance.md is protected".

So `acceptance.md`, `build-notes.md`, `reviews/`, `diagnosis.md`, `summary.md` and `decision-requests/draft.md` had nowhere to go.

## What V1.1 changes

A job's files now live in two places, split by who writes them. The definition is in [`factory/README.md`](../README.md), "Where things live".

- **The job's folder moves into the worktree**, `<worktree>/factory/.jobs/<n>/`, gitignored like before: `issue.md`, `acceptance.md`, `build-notes.md`, `checks/`, `gate.json`, `reviews/`, `decision-requests/`, `diagnosis.md` and `summary.md`. The CLI writes `checks/`, `gate.json` and the posted Decision Requests there too, because agents read them.
- **The job's state stays in the main checkout**: `job.json`, `events.jsonl`, the checks lock and the CLI's own logs. Only the CLI and the hooks write them, and neither is confined. The 3-job limit and `factory status` read every job in one place, and the record survives the worktree.
- **The area resolver places the worktree's job folder in the `job` area** (`locate` in `cli/src/events.ts`, fed by `handoffDir` in `cli/src/job.ts`). The guard hook and `factory watch` share it. The rest of `factory/` in the worktree stays a protected `repo` path, and the main checkout, its copy of the job's folder included, stays `outside`.
- **`factory start` creates the job's folder in the worktree**, writes `issue.md` there and prints its path as `handoff`. On an existing job it copies in any handoff file that exists only in the main checkout, never overwriting one already in the worktree, so jobs started under V1 resume.
- **No symlinks.** Auto mode blocks them because they sidestep its oversight, and a path through one would resolve to a different area than it reads as.

## What was learned

- **A worktree confines writes, not only the working directory.** After `EnterWorktree`, Claude Code refuses a `Write` or `Edit` outside the worktree for the session and its subagents. Hooks and the CLI, run as commands, are not confined, so they can keep state in the main checkout.
- **A path's area must follow where agents can write.** V1's areas were drawn by meaning (the job's folder versus the repo) without checking which paths a confined session reaches. The guard's tests now drive the hook end to end, from the session to the verdict, on real paths in a throwaway checkout (`cli/src/commands/hook.test.ts`); run against V1's code they fail exactly as job #13 did.
