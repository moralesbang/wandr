# Factory V1

Date: 2026-11-26

## The need

Wandr is a portfolio project built to practice senior engineering with AI-assisted development. The user is product owner, architect and reviewer; agents implement. Doing that by hand, one prompt at a time, leaves the isolation between writing, building and judging to chance, and gives the user nothing to inspect afterward.

A software factory makes that process explicit: a GitHub issue goes in, a pull request comes out, and each step is either a deterministic check the agents can't change or an agent that starts from only its own inputs. The goal of V1 is to learn to build one by iterating: the smallest version that works end to end, then a V2 when a real need shows up.

## What V1 does

An issue with numbered acceptance criteria and the label `factory:ready` becomes a pull request. A test agent writes the acceptance tests and a CLI accepts the red only if every test fails on an assertion. A build agent implements until the local CI checks pass. An evaluator and a test reviewer, each in its own context and with a blind first pass, review in an outer loop. The CLI opens the PR; the user reviews and merges. `factory watch` shows every job live and flags isolation breaches.

The definition lives in [`factory/README.md`](../README.md).

## What was learned

- **Subagents can spawn subagents.** The brief assumed a background subagent has no Agent tool. In Claude Code 2.1.332 subagents can spawn their own, up to 3 levels deep. Background subagents do lose `AskUserQuestion`. [Subagents](https://code.claude.com/docs/en/sub-agents), "Let subagents spawn their own subagents".
- **Hooks belong in `.claude/settings.json`.** Hooks declared in a skill's frontmatter don't fire inside subagents; settings hooks do, carrying the parent's `session_id` plus `agent_id` and `agent_type`. The skill passes `${CLAUDE_SESSION_ID}` to `factory start`, so hooks map a session to its job. [Hooks reference](https://code.claude.com/docs/en/hooks).
- **`InstructionsLoaded` carries `agent_id` inside subagents** (nested `CLAUDE.md` files, `load_reason: nested_traversal`). The root `CLAUDE.md` loads once at session start, with no per-subagent event.
- **The Agent tool's hooks hold what the page needs.** `PreToolUse` carries `prompt`, `subagent_type`, `description` and `run_in_background`; `PostToolUse` returns `tool_response.agentId`.
- **A hook guards writes, not Bash.** A synchronous `PreToolUse` hook denies Edit and Write outside an agent's write scope, but Bash can bypass it, so the CLI's gate stays the final verdict. Subagents ignore `permissionMode` in auto mode. Files a Bash command changes are attributed with a git snapshot at `SubagentStart` and `SubagentStop`.
- **JUnit reports differ per runner, so the valid red is per runner.** Verified with `bun test` 1.4.2, Vitest 5.1.1 and Playwright 1.65.1:
  - `bun test`: a failed assertion gives `<failure type="AssertionError">`; a load error drops the file from the report.
  - Vitest: a failed assertion gives `type="AssertionError"`; a load error gives a testcase named after its file.
  - Playwright: a failed assertion gives `<failure type="expect.*">`; a click on a missing element gives `<error type="TimeoutError">`, which is why end-to-end tests assert visibility first; a load error gives an empty run.
  - The reports are kept as fixtures in `factory/cli/src/junit-fixtures/`.
- **The diagrams are unvalidated by a renderer.** Rendering Mermaid locally was blocked by the auto-mode classifier, so the diagrams in the README were checked by reading only.

## V2 candidates

- A dedicated refactor station after green.
- Hidden acceptance tests held back for the reviewers, when the risk justifies them.
- Mutation testing on the diff only, so the score never becomes a target.
- Property-based tests for invariants.
- Contract tests.
- Traceability per acceptance criterion.
- A risk level per issue that scales verification.
- Coverage as a diagnostic for the evaluator.
- A second-opinion evaluator on another model family.
- Calibrating the reviewers against the user's verdicts.
- A cost budget per job.
- Enforcing escalation in the CLI, not only by instruction.
- Blocking isolation breaches with a synchronous `PreToolUse` hook instead of only flagging them: start with `Read` breaches.
- Classifying `Grep`, `Glob` and `Bash` reads in the breach rule, not only `Read`.
