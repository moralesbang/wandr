# Factory V1.2

Date: 2026-11-26

## The need

Job #13 (a favicon and app icons) resumed on V1.1 and blocked again, on the factory's own faults rather than the issue's:

- **`factory check` broke every multi-line CI step.** It built `bash … -c ${JSON.stringify(run)}` and ran that string through `sh -c`. `JSON.stringify` turns each newline into a literal `\n`, which inside double quotes is no newline, so "Generated files match the code", a `run: |` block with a `\` continuation and a `|| { …; exit 1; }` group, reached bash as one line: `syntax error: unexpected end of file`. The outer `sh` also expanded `$VAR`s and backticks before bash saw them. The job's last check failed there, on code that was fine.
- **Each worktree started its own Docker stack.** Compose names a project after its folder, so `bun run services` in the job's worktree started `13-ux-…` beside the main checkout's `wandr` stack, both on ports 5432 and 9000. The worktree's `s3` container reported healthy with no network at all (`Networks: {}`), and `buckets` failed: "Could not connect to the endpoint URL http://s3:9000". The checks lock already assumed one shared stack.
- **`factory red` accepted acceptance tests CI rejects.** `apps/web/e2e/icons.spec.ts` used `.sort()` (lint's `unicorn/no-array-sort`) and wasn't formatted with oxfmt. The red passed; CI's lint and Format steps then failed after the build, and it took two `factory atfix` runs, two same-guarantee fixes that should never have been needed.
- **A job couldn't be discarded.** `factory clean` refuses any job whose PR isn't merged, so a job blocked on the factory itself had no way back to a clean start.

## What V1.2 changes

The definition is in [`factory/README.md`](../README.md).

- **A CI step's script is one argument to bash.** `shellOf` returns `['bash', '--noprofile', '--norc', '-eo', 'pipefail', '-c', run]` and `runLogged` spawns that argv with no shell around it, sending stdout and stderr to the log from `Bun.spawn`. Every caller (`start`, `red`, `check`) passes an argv, so nothing in the CLI quotes for a shell any more. The tests run a one-line step, a multi-line step with a continuation and a `{ …; }` group, and a step whose `$VAR` and backticks only bash may expand; against V1.1's code they fail with job #13's error.
- **One Docker stack for every checkout.** `docker-compose.yml` sets `name: wandr`. Postgres's init SQL moved from a bind mount (`./docker/postgres-init.sql`) into an inline compose `config`: a host path resolves differently in each worktree, so compose recreated postgres whenever another checkout ran `bun run services`, restarting the database under the main checkout's dev server. Verified by hand: from the main checkout and then a worktree, the same containers keep their IDs, no volume or network is created, and a database and an object written before survive.
- **`factory red` checks lint and format first.** It runs the worktree's `oxlint --deny-warnings` and `oxfmt --check` on the new or changed acceptance test files, then the tests, and one rejection lists every problem with its file and the command that fixes or checks it. The test agent runs both before it finishes (`.claude/agents/factory-test.md`).
- **`factory clean <n> --abandon`.** It records `job.abandoned`, takes down a compose stack the worktree started on its own (with its volumes, never the shared `wandr`), removes the worktree and the branch locally and on `origin`, deletes the job's state folder and moves the label back to `factory:ready`. It refuses while the branch has an open PR, and when it merged. `factory watch` forgets a job whose folder is gone, so an issue that starts again shows its new log from the start.

## What was learned

- **Never build a shell command from a string you didn't write.** The CI scripts are data. Each layer of shell between the CLI and bash re-reads them; argv passes them through untouched.
- **A worktree is another folder to every tool that derives a name or a path from it.** Claude Code confines writes to it (V1.1), and compose names its project after it and resolves its bind mounts from it. Anything shared across jobs has to be named, not derived.
- **A red is only as good as the first CI step that would reject it.** Lint and format are the cheapest of those, and the build agent can't touch acceptance tests to fix them.
